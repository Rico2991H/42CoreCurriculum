42 Core Curriculum

My projects from the core curriculum at 42 Berlin, a peer-to-peer coding school with no teachers or lectures. You learn by building projects in C and C++ to strict specifications, and your fellow students review and grade the code.

Highlights
Project	Language	What it does
Minishell	C	A Bash-like shell with pipes, redirections, heredocs, environment variables, signals, built-ins, and && / || with parentheses and * wildcards (bonus). Built in a team of two.
cub3D	C	A Wolfenstein-style first-person 3D renderer using raycasting, textured walls, map parsing and validation, and a minimap. Built in a team of two.
Philosophers	C	The dining philosophers problem, solved with threads and mutexes, plus a bonus version with processes and semaphores.

What I took away
How a computer actually works underneath. Managing memory by hand, handling file descriptors, and creating processes and threads with system calls taught me what higher-level languages normally hide.
Debugging without a safety net. Tracking down memory leaks, race conditions, and undefined behavior with tools like Valgrind and GDB.
Working with other people's code. Every project gets reviewed by fellow students, and the larger projects were built in pairs. So explaining my design choices, and reading code I didn't write, became part of daily work.
